# Deploying the viewer to GitHub Pages The `vwap-viewer/` folder is a complete, ready-to-publish static site. Follow these steps to put it online for free at `https://YOUR-USERNAME.github.io/vwap-viewer/`. --- ## Option A — GitHub website only (no command line) 1. **Create the repository** - Go to https://github.com/new - Repository name: `vwap-viewer` - Set it to **Public** (Pages is free for public repos) - Do NOT add a README/gitignore (the folder already has them) - Click **Create repository** 2. **Upload the files** - On the new repo page, click **uploading an existing file** - Drag **the contents of the `vwap-viewer` folder** (not the folder itself) into the upload area: `index.html`, the `data` folder, `README.md`, `.gitignore`, and `.nojekyll`. - If the browser won't let you drag the `data` folder, drag its files in and put them under a `data/` path, or use Option B below (Git handles folders cleanly). - Scroll down, click **Commit changes** 3. **Turn on Pages** - Repo → **Settings** → **Pages** (left sidebar) - Under **Build and deployment**, Source = **Deploy from a branch** - Branch = **main**, folder = **/ (root)** → **Save** 4. **Wait ~1 minute**, then open `https://YOUR-USERNAME.github.io/vwap-viewer/` You should see the header tag **build v9** and the Chart/Calendar tabs. --- ## Option B — Git command line (better for updates) From inside the `vwap-viewer` folder: ```bash git init git add . git commit -m "VWAP trade viewer" git branch -M main git remote add origin https://github.com/YOUR-USERNAME/vwap-viewer.git git push -u origin main ``` Then do step 3 above (Settings → Pages → deploy from `main`, root). To update the site later (after regenerating data or editing `index.html`): ```bash git add . git commit -m "update" git push ``` The live site refreshes automatically within a minute or so. --- ## After it's live - Edit `README.md` and replace `YOUR-USERNAME` with your GitHub username so the link works. - **Hard-refresh** (Ctrl+Shift+R) after each update — the browser caches aggressively. The `build vN` tag in the header tells you which version loaded. ## Gotchas - **Keep `.nojekyll`.** Without it, GitHub Pages runs Jekyll, which can ignore or mangle files/folders. It must sit next to `index.html`. - **Upload the `data/` folder too.** Same rule as running locally — the page fetches `data/index.json`, `data/calendar.json`, and the per-year files. No data folder → the page loads but hangs on "select a day" with 404s. - **Public repo = public site and data.** Anyone with the URL can view it. For a private site, GitHub Pages requires a paid plan; alternatively host on Cloudflare Access or password-protect via another provider. - The raw `*_ohlcv-1m.csv` files are intentionally excluded by `.gitignore` — they're huge and the site doesn't need them.
